---
title: "Onboarding"
description: "Drive the project setup wizard with website extraction, brand research, audience segments, topics, questions, and competitor suggestions."
---

The onboarding endpoints power the create-project wizard. They run AI analysis
on your behalf and return structured JSON ready to feed into
`POST /api/v1/orgs/{orgId}/projects/setup`.

Generation uses a more capable LLM model, with an automatic fallback model if
the primary model is unavailable.

<Note>
  All onboarding endpoints require an authenticated session. They do not require
  an active subscription, so trial and pre-purchase users can run the wizard.
</Note>

<Note>
  **Generation behavior**

  - **Exact-count requests.** When `requestedCount` or `promptsPerTopic` is
    supplied, the backend asks for exactly that many and runs bounded top-up
    passes when the model replies short, using the rows it already has as an
    avoid list. In normal operation the count matches; a degraded model may
    return fewer rather than failing the request.
  - **Market-level, unbranded questions.** The brand name and marketing claims
    are not sent to the topic/question model. Questions must be answerable by
    several businesses in the same category and market, so competitors can
    appear in the same answers.
  - **Caching.** First-generation results are cached for 7 days. Send
    `variation` greater than `0` to bypass the cache and request a fresh set.
  - **Bounded inputs.** `audiences` accepts up to 10 segments; `avoidTopics`
    accepts up to 30 topic names.

  The live machine-readable schema is available at
  [https://api.visibilitysuite.ai/api/v1/openapi](https://api.visibilitysuite.ai/api/v1/openapi).
</Note>

## Extract website content

**POST** `/api/v1/onboarding/extract-website`

Scrapes the main textual content of a URL using web extraction. Used as the
input to brand research and competitor search.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `url` | string | body | yes | Site URL to scrape. |
| `industry` | string | body | no | Optional industry hint. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/extract-website \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://acme.example","industry":"Software & SaaS"}'
```

```json
{
  "content": "Acme builds CRM software for small businesses...",
  "url": "https://acme.example"
}
```

## Describe brand and audience

**POST** `/api/v1/onboarding/describe-brand`

Starts brand research. The backend checks a 7-day cache, then runs a web
research job. If that is unavailable, it falls back to a direct site scrape plus
structured AI analysis. The result contains a brand profile and ordered audience
segments.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `businessName` | string | body | yes | Brand name. |
| `url` | string | body | yes | Brand URL. A deep link is allowed. |
| `industryHint` | string | body | no | Industry hint. |
| `variation` | number | body | no | `0`–`25`. `0`/omitted uses the cache; `> 0` requests a fresh profile. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/describe-brand \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "businessName": "Acme",
    "url": "https://acme.example",
    "industryHint": "Software & SaaS"
  }'
```

Returns either a job handle or a completed result. A cache hit and the
synchronous fallback return the completed form immediately.

```json
{ "jobId": "job_abc123" }
```

```json
{
  "status": "completed",
  "describe": {
    "description": "Acme builds CRM software for small sales teams...",
    "industry": "Software & SaaS",
    "location": "Portland, Oregon, USA",
    "language": "English",
    "productsServices": ["CRM", "Pipeline tracking", "Email sequences"],
    "brandIdentityTags": ["small business", "sales operations"],
    "detectedThemes": ["easy setup", "affordable"],
    "contextNotes": "Serves SMBs in the Pacific Northwest."
  },
  "audienceSegments": [
    {
      "name": "Small business owners",
      "description": "Owners evaluating their first CRM.",
      "priority": 1,
      "enabled": true
    },
    {
      "name": "Sales managers",
      "description": "Managers standardizing a sales process.",
      "priority": 2,
      "enabled": true
    }
  ]
}
```

`audienceSegments` is ordered by importance: `priority: 1` is the primary
audience. Percentages are not returned.

## Poll brand research

**GET** `/api/v1/onboarding/describe-brand/status/{jobId}`

Polls an async job created by `describe-brand`.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `jobId` | string | path | yes | Job handle from `describe-brand`. |

```json
{ "status": "running" }
```

```json
{
  "status": "completed",
  "describe": {
    "description": "CRM software for small sales teams.",
    "industry": "Software & SaaS",
    "location": "Portland, Oregon, USA",
    "language": "English",
    "productsServices": ["CRM", "Pipeline tracking"],
    "brandIdentityTags": ["small business"],
    "detectedThemes": ["easy setup"],
    "contextNotes": "Serves SMBs in the Pacific Northwest."
  },
  "audienceSegments": [
    { "name": "Small business owners", "priority": 1, "enabled": true }
  ]
}
```

```json
{ "status": "failed", "error": "Brand research is taking too long. Try again." }
```

Jobs expire after 15 minutes. A `failed` response means the job is gone or the
fallback failed; retrying `describe-brand` is safe and usually hits the cache.

## Suggest topics

**POST** `/api/v1/onboarding/topics`

Suggests market-level topic clusters used to group questions. The wizard
requests 10 topics by default.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `businessName` | string | body | yes | Brand name. Used for sanitation, not sent to the model. |
| `industry` | string | body | yes | Industry label. |
| `location` | string | body | yes | Market or location. |
| `description` | string | body | yes | Brand description. Brand mentions are neutralized before generation. |
| `productsServices` | string[] | body | yes | Product/service list. |
| `requestedCount` | number | body | no | Exact number of topics to return. The wizard sends 10. |
| `audiences` | object[] | body | no | Priority-ordered segments: `{ name, description?, priority }` (max 10). |
| `avoidTopics` | string[] | body | no | Existing topic names a regeneration must not repeat (max 30, each ≤ 200 chars). |
| `variation` | number | body | no | `0`–`25`. `0`/omitted uses the cache; `> 0` forces a fresh set. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/topics \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "businessName": "Acme",
    "industry": "Software & SaaS",
    "location": "Portland, Oregon, USA",
    "description": "CRM for small sales teams.",
    "productsServices": ["CRM", "Pipeline tracking"],
    "requestedCount": 10,
    "audiences": [
      { "name": "Small business owners", "priority": 1 },
      { "name": "Sales managers", "priority": 2 }
    ]
  }'
```

```json
{
  "topics": [
    {
      "name": "CRM software for small teams",
      "description": "Tools small sales teams use to manage leads and follow-ups."
    },
    {
      "name": "Sales pipeline tools",
      "description": "Platforms that visualize and automate a sales pipeline."
    }
  ]
}
```

When `requestedCount` is supplied, the array is sliced to that count and the
backend tops up short model replies with additional passes before returning.

## Generate questions for one topic

**POST** `/api/v1/onboarding/prompts`

Generates the questions a real customer would ask an AI assistant for one topic.
Each row includes the question text, an estimated monthly search volume, and an
intent label.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `topicName` | string | body | yes | Topic to generate for. |
| `topicDescription` | string | body | no | Topic description; steers the angle. |
| `businessName` | string | body | yes | Brand name. Used for sanitation, not sent to the model. |
| `industry` | string | body | yes | Industry label. |
| `location` | string | body | yes | Market or location. |
| `description` | string | body | yes | Brand description. Brand mentions are neutralized before generation. |
| `requestedCount` | number | body | no | Exact number of questions to return. The wizard sends 5. |
| `avoidTexts` | string[] | body | no | Existing questions a regeneration must not repeat. |
| `siblingTopics` | string[] | body | no | Other topic names, so the model stays in this topic's lane. |
| `audiences` | object[] | body | no | Priority-ordered segments: `{ name, description?, priority }` (max 10). |
| `variation` | number | body | no | `0`–`25`. `0`/omitted uses the cache; `> 0` forces a fresh set. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/prompts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "topicName": "CRM software for small teams",
    "topicDescription": "Tools small sales teams use to manage leads.",
    "businessName": "Acme",
    "industry": "Software & SaaS",
    "location": "Portland, Oregon, USA",
    "description": "CRM for small sales teams.",
    "requestedCount": 5,
    "siblingTopics": ["Sales pipeline tools", "CRM alternatives"],
    "audiences": [{ "name": "Small business owners", "priority": 1 }]
  }'
```

```json
{
  "prompts": [
    {
      "text": "What is the best CRM for a small sales team?",
      "estVolume": 1200,
      "intent": "informational"
    },
    {
      "text": "Which CRM tools are easiest to set up for a five person team?",
      "estVolume": 320,
      "intent": "comparison"
    }
  ]
}
```

`intent` is one of `informational`, `transactional`, `navigational`, or
`comparison`. `estVolume` is an integer estimate, not a keyword-tool value.

When `requestedCount` is supplied, the backend targets that exact count and
tops up short replies the same way as the topics endpoint.

## Generate questions for every topic

**POST** `/api/v1/onboarding/prompts/batch`

Generates questions for several topics in one request. The backend fans out to
the model with bounded concurrency, removes cross-topic duplicates, and retries
any topic that ends up under-filled or whose call failed.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `topics` | object[] | body | yes | `{ name, description? }` — at least one topic. |
| `businessName` | string | body | yes | Brand name. |
| `industry` | string | body | yes | Industry label. |
| `location` | string | body | yes | Market or location. |
| `description` | string | body | yes | Brand description. |
| `promptsPerTopic` | number | body | no | Exact number of questions per topic. The wizard sends 5. |
| `audiences` | object[] | body | no | Priority-ordered segments (max 10). |
| `variation` | number | body | no | Forwarded to every per-topic call for regeneration. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/prompts/batch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "topics": [
      { "name": "CRM software for small teams", "description": "Tools for small sales teams." },
      { "name": "Sales pipeline tools", "description": "Pipeline visualization and automation." }
    ],
    "businessName": "Acme",
    "industry": "Software & SaaS",
    "location": "Portland, Oregon, USA",
    "description": "CRM for small sales teams.",
    "promptsPerTopic": 5
  }'
```

```json
{
  "prompts": [
    {
      "text": "What is the best CRM for a small sales team?",
      "estVolume": 1200,
      "intent": "informational",
      "topicName": "CRM software for small teams"
    },
    {
      "text": "Which CRM tools have the simplest pipeline setup?",
      "estVolume": 450,
      "intent": "comparison",
      "topicName": "Sales pipeline tools"
    }
  ],
  "failedTopics": []
}
```

`failedTopics` lists only topics that still have zero questions after the
retry/top-up pass. A topic with some questions is returned with what it has.

## Suggest competitors

**POST** `/api/v1/onboarding/competitors`

Suggests competitor brands using web search plus AI reasoning. Returns name,
URL, and a reason for each suggestion.

| Name | Type | In | Required | Description |
| --- | --- | --- | --- | --- |
| `businessName` | string | body | yes | Brand name. |
| `url` | string | body | yes | Brand URL. |
| `industry` | string | body | no | Industry hint. |
| `location` | string | body | no | Geo context. |
| `description` | string | body | no | Brand description. |
| `productsServices` | string[] | body | no | Product/service list. |
| `existingNames` | string[] | body | no | Already-known competitor names to avoid. |
| `variation` | number | body | no | `0`–`25`. `> 0` requests a fresh search. |

```bash
curl -X POST https://api.visibilitysuite.ai/api/v1/onboarding/competitors \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"businessName":"Acme","url":"https://acme.example"}'
```

```json
{
  "competitors": [
    { "name": "Globex", "url": "https://globex.example", "reason": "Direct CRM competitor for SMBs." }
  ]
}
```

## List allowed industries

**GET** `/api/v1/onboarding/industries`

Returns the curated list of industry labels accepted by the onboarding and
project setup flows.

```bash
curl https://api.visibilitysuite.ai/api/v1/onboarding/industries \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "industries": [
    "Advertising & Marketing",
    "Automotive",
    "Software & SaaS",
    "E-commerce"
  ]
}
```
