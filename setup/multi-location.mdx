---
title: "Multi-location tracking"
description: "Set up monitoring for chains and franchises: one project per location, subfolder tracking, and the cross-location report."
---

Visibility Suite scales from a single shop to a multi-location brand. Two building blocks cover most setups: one project per location, or a single project that tracks a subfolder of a shared website.

## Option 1: one project per location

Create a separate project for each location. Each gets its own market-anchored prompts, its own local competitors, and its own scores. This is the right choice when locations operate in genuinely different markets (different cities, different competitor sets), or when each location has its own website.

On your organization dashboard, all projects appear side by side. Use tags to group them by region, brand, or manager.

## Option 2: subfolder tracking

If all your locations live on one website under paths like `example.com/locations/austin`, a single project can track just that subfolder. Citations are then matched only within that URL boundary: a citation of your Austin page counts for the Austin project, not for the whole domain.

Choose subfolder mode when one website serves all locations and you want per-location reporting without splitting the domain. You set it during onboarding with "Track this subfolder only".

## Handling your own other branches

When an AI answer about Austin mentions your Dallas branch, that is not a competitor win. Mark the other locations as "same brand, other location" in Brand Hub. Their mentions are separated from true competitors in rankings and share of voice, keeping each location's report honest.

## The cross-location report

For the bird's-eye view, the cross-location report lines up every project in your organization side by side. For each location you see the latest snapshot: visibility score, mentions, citations, average sentiment, recommendation rate, and the date of the last run, plus the tracked subfolder path where one is set.

Use it to spot which locations are winning AI recommendations and which are invisible, then drill into a lagging project's Overview to see why.

## Which setup should you choose?

| Situation | Recommended setup |
| --- | --- |
| Each location has its own website | One project per location |
| One website with location subfolders | One project per location, each in subfolder mode |
| Locations share one market and one site | A single project may be enough |
| Franchisees manage their own marketing | One project per location, tagged by owner |

<Note>
  Your plan limits how many projects you can run, and extra project slots are available as an add-on. See [plans and billing](/account/plans-and-billing).
</Note>
